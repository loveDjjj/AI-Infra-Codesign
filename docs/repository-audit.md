## 推荐的稳定目录

```text
AI_Infra/
├── README.md, AGENTS.md, lab, pyproject.toml, requirements.lock
├── configs/                 # 基线、根源码最佳、活跃搜索与流水线配置
├── src/codesign_lab/        # 构建、生成器、评估、搜索、模型桥接与发布
├── schemas/, tests/, scripts/
├── docs/                    # 5 份核心说明 + 本审计 + 课程原文；dashboard.html 本地生成
├── data/                    # 账本、决策、状态、迭代记录；原件本地受保护
├── vendor/official/         # 冻结工具
└── workspace/               # 可再生运行现场，不入 Git
```

当前模块划分已能表达硬件/软件、评估和搜索职责。现在整体搬迁 `src/`、合并几十个 search 模块或复制新的“平台目录”会增加导入与源码身份风险，收益不明显。优先收紧边界、入口与事实源。`codegen/d1/` 的九个历史命名文件是实际继承闭包，不应仅凭名字删除。

## 工作流应回答的五个问题

1. **当前从哪一版开始？** 根源码最佳、最高已审计隔离源码与网站已提交版本分别查 `state.json`、账本、回执。
2. **一个目标改了什么？** 候选配置和构建后的硬件/P1/D1 ASM 哈希必须一并记录；参数未生效不送冷模拟。
3. **观察是否可靠？** 功能、局部时序、功耗、官方整案和审计不同级；超时/OOM 不等于性能退化。
4. **下一轮为何这样搜？** AI 决策指向证据 ID、适用范围和预算；硬剪枝与经验降权分离。
5. **怎样发布？** 官方原始报告、隔离再生、ZIP 校验、人工轨迹与网站提交分开。GitHub push 只发布项目代码。

## GitHub 与课程材料边界

本次 Git 提交保留代码、测试、配置、中文说明和轻量事实记录。课程要求的完整 `agent-trace/` 不因 Git 忽略而消失；它仍在本机唯一受保护目录，并由 `lab package` 选入课程 ZIP。`data/releases/`、`data/evidence/` 和 starter ZIP 也仍在本机。GitHub 不应当被当作这些原件的唯一备份。已存在的旧 Git 历史含大文件；本次不重写历史，因为重写会改变远端提交身份和协作基础。

最高分的隔离源码仍在嵌套 `workspace/implementation-loop/.../source`，但**并非只有这一份**：受保护 `data/releases/official-1790581630771528243/generator-source.tar.gz` 已含完整 `src/`。本轮从该归档隔离重建，硬件及两份 ASM 与发布原件逐字节一致。下一步应登记其来源哈希并独立备份，必要时通过专用 Git 分支提供可取回源码；不要把整个 1.8 GiB 的嵌套工作区上传。对应方案在 [自动化方案](automation-plan.md)。

课程打包实测：joint28 ZIP 为 24,293,083 字节，展开后 57,270,065 字节；`lab verify` 校验了清单、课程轨迹原始哈希、官方原件和三份产物的独立再生。该测试验证的是 joint28 的打包链路，不代表隔离 epoch 的 49,283 分版本已打包。
