# 已知经验与证据边界

## W2 split K + owner 常驻

局部宽阵列/cache0 测试周期 60,223 → 30,689，HBM 读取 6.85 MB → 2.10 MB。只是一组冷启动局部对照，不能直接按三层叠加整案收益。

joint27 合入后 P1 394,748 周期但峰值 21.2578 W，超过门槛。joint28 保留 W2 owner，实现 QKV/WO 常驻、W1 K32 分段加载和 decode 计算覆盖加载，P1 403,197 周期、19.1436 W；D1 43,523 周期、15.7863 W；整案分数 47,957.06。功耗修复略牺牲周期，换取合格整案。

## 资源压力不等于因果瓶颈

joint28 P1 NoC 忙碌比例约 48.01%，最高 SM RF read 36.97%，TC 20.70%。数据搬运是优先验证方向，但无法仅靠这些比例证明 HBM bound 或同步 bound。

等待代理 = 1 - 最大实体容量归一化占用率。它描述未覆盖容量，可能包括工作不足、依赖、同步和负载不均，不能当成真实 stall 百分比。issue_wait_cycles 是官方累计指标，可以超过总周期，不与资源比例相加。

算子源指令范围与官方展开事件的 line 精确关联；issue-to-finish 跨度实测，但并发和嵌套阶段不能相加。阶段内资源压力来自时间分箱加权，标记低置信度估计，不能归属所有共享流量给单个算子。

## 更快的探索评估

结果缓存绑定 ASM、硬件、工作负载、官方引擎和环境；功能检查还包括种子。结构重构未更改官方工具。硬约束和历史经验排序分离：超面积能剪枝，历史超功耗不能永久禁止一种硬件配置。

## 初始调研保留的方向

早期基线只使用 SM0；加 SM 本身不带来自动并行。扩大分块、增加独立输出分片、减少搬运与融合应联合验证。完整初始调研和课程声明快照保存在 docs/assignment/，不将历史猜测升级成当前结论。

## 预载粒度与并行吞吐的最新验证

固定 joint28，W1/W2 单独改预载 K16 均为 P1 403,149 周期（比基准少 48），K64 均为 403,221；W1 K64 峰值 20.0575 W 超限。四个候选 seed 7 功能通过。该维度收益不足以刷新提交，后续不优先扩大。

四个相同 D1 冷任务 seed 7/123：串行 230.86 秒，4 进程 70.61 秒，吞吐 3.27 倍，周期、功耗与功能通过状态一致。仅证明这组任务的吞吐改善，不外推 32/64 进程的加速。冷基准原件已清理；实验指标已写入账本。


## D1 cache/SFU 四点冷对照（parallel-stage-cold-d1-v1）

观察：同一当前 D1 程序，cache0/SFU8 为 43,523 周期；SFU4 为 44,067。cache1/SFU8 为 51,781、11.0874 W，而 cache0/SFU8 为 15.7863 W。四种输入均通过 seed 7/123。记录 ID 为 parallel-stage-cold-d1-v1-input0..3。

适用范围：本轮硬件与 D1 常驻软件实现；尚无同硬件 P1/整案对照。cache1 更慢但功耗低，不能据此永久剪掉 cache1。若修改常驻/加载策略，需要重新验证交互。

评估链路：四候选、4 worker 的冷 both/split 对照结果完全相同；64.01/64.74 秒，未证明拆分提高吞吐。分阶段的主要已验证价值是恢复与测量边界，新的吞吐假设应针对异构阶段队列与实际搜索任务。

在 joint28 硬件与 SplitW2Builder 上，w2_load_group_size 默认16为43,523周期；8为44,623，4为48,890。seed7/123均通过，峰值功耗同为15.7863W。原始工作区报告已清理，关键事实和完整配置保留在实验账本。

2026-09-28 在已审计 49,283.865188 分的冻结实现族上，经动态目标 `d1-family-group8` 再测同硬件对照：分组16为 41,883 周期、17.8528 W；分组8为 42,737 周期、17.6795 W，均通过 seed 7/123。新实现族仍表现为较小分组使 D1 变慢，功耗略降；这只覆盖该源码版本和 D1 单案，不能作为跨实现族的硬剪枝或整案得分推断。事实 ID 为 `family-dynamic-smoke-case-7a881a30516128109dc8c6d1833a79b8d53c4b6a62bc67e4fa4c57028d24ff20` 与 `family-dynamic-smoke-case-9fefd3b9905d8d387829aa475276bda10725b834265fb231ef309cfcaaab6e4e`。

## D1 W2 按K分片加载输入：隔离实现有效，待合入

在双归约硬件、已审计48,531.58分版本上，原W2每个shard将512个输入元素加载到RF0，实际只消费所属K256。隔离源码增加默认关闭的`w2_half_input_load`，把输入加载改为对应的256元素，MMA输入偏移改为分片内偏移。默认关闭时joint28硬件及两份ASM逐字节一致；打开后D1 seed7/123功能通过，单案43,139→42,467周期（约1.56%），峰值功耗15.7983W不变。隔离官方整案合格并审计，48,914.05分；P1仍为397,212周期。原始诊断目录已清理，关键结果与适用条件保留于本节和实验账本。

适用范围是当前SplitW2Builder、K512拆成两个K256的实现。此实验只证明当前数据加载改动的收益；不能推断所有W2的等待都来自输入搬运。主自动批次仍冻结旧源码，因此该隔离结果尚未成为主线配置或提交包。合入时需重新核对当前主线源码、两案功能与官方整案。

## P1 W2 去除每行全局屏障：周期和功耗退化

在同一已审计双归约硬件/软件起点上，隔离源码增加默认关闭的`w2_skip_row_barrier`，只移除W2 M16循环中的逐行全局屏障，末尾屏障保留。默认关闭时joint28三份产物逐字节一致；打开后P1 seed7/123功能通过，但397,212→398,172周期，峰值功耗19.1556→21.6978W，超过20W门槛。因而拒绝与D1有效改动组合。原始诊断目录已清理，关键指标与失败原因保留于本节和实验账本。

这证明当前调度下直接删屏障不可行；它可能改变权重/输入加载与计算的重叠及瞬时资源压力，但单次对照不能证明具体因果等待。下一种同步优化必须保持功耗门槛，并用事件依赖与profile逐段验证，不能只数少了几条barrier。

解释：这里的改动增加了冷加载组间全工作组同步，当前对照没有看到峰值功耗下降，不能把“小组加载”泛化成更省功耗。降低该三点空间的优先级；若将来改变同步范围、预取重叠或布局，应视为不同假设重新验证，不能用本结果硬剪掉所有分组实现。

## P1 W2 限功耗错峰：单案改善，整包被旧 D1 拖低

在结构批次 `structure-staged-20260928` 的冻结 48,561.111102 分源码上，错峰限流版 W2 的 P1 从 396,729 降到 394,545 周期，峰值 19.270363 W，seed 7/123 功能通过。官方整案合格、已审计，48,695.330395 分；该源码的 D1 为 43,139 周期，慢于先前最高整包版本的 D1 41,883 周期，因此不能用整包低分否定 P1 机制。P1 单案最佳源码仍作为最高分组合来源保留，其他较低分原件已清理；完整配置与单案指标留在账本。同硬件跨源码组合经各自生成器逐字节再生，官方整案为 49,420.082119 分并已审计，较旧最高分高约 136.22 分；受保护原件在 `data/releases/pair-w2-throttle-highest-full-1790611520350037544/`。

后续搜索应按同硬件、同案例选择可再生的最快合格基线，再组合整案。当前结构实验入口已按此规则选择 P1 394,545 与 D1 41,883 周期版本；不同硬件或同一案例内的两种修改仍需独立整合验证。

## M2 行块 FFN 流水化：权重重载量压倒激活节省

首版 `ffn_rf_m2` 保留 W1/GELU/W2 的数学顺序并通过 P1 seed 7/123 功能，但每层 64 个 M2 行块各自加载约 1 MiB W1 与 1 MiB W2 权重，静态逻辑加载约 128 MiB，设想省去的中间激活读写约 1 MiB。单案计时持续超过 41 分钟未完成，主动停止；**没有周期、功耗或实测 HBM 流量结论**。临时代码与运行状态已清理；没有可复现的周期、功耗或 HBM 实测结论，后续应按新假设重新实现。

下一种 FFN 融合必须先证明权重复用或更大 M 块可降低重复加载，再进入昂贵时序仿真。静态逻辑字节数只用于排序和筛查，不能直接当作 HBM 实测值。
