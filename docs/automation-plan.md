# 自动优化：持续供给与结构研究

目标是在固定墙钟、CPU、内存和官方验收预算内，持续发现更优的合格 HW–SW 设计。芯片周期、峰值功耗、面积和官方得分衡量设计；有效新产物率、冷评估次数和最佳分数随墙钟变化衡量研究效率。缓存命中不能当作芯片提速。

## 工作单位与事实来源

研究按三层推进：**结构假设 → 冻结实现族 → 具体候选**。假设说明改变哪种开销及便宜的否证实验；实现族包含源码、基准候选和有限合法种子；具体候选才进入构建、功能和时序评估。代码负责实现，配置负责设计，`data/experiments.jsonl` 负责事实，`docs/knowledge.md` 负责解释。AI 决策留在 `data/decisions.jsonl`，课程代理轨迹只维护 `data/agent-trace/` 一份。

统一路径：

```text
审阅过的假设池 / AI 新假设
  → 隔离源码编码 → 默认三产物逐字节再生 → 回归、静态和功能检查
  → 单案时序 → 同硬件兼容 P1/D1 候选集合
  → 分别按冻结来源再生、验证组合 → 未修改的官方整案 → 审计
```

单案提速、组合推算、整案合格、已审计和已发布是不同状态。结构单案通过后**先进入组合器**；只有明确需要单一源码的正式证据时才额外跑该源码的独立整案。跨源码组合必须核对硬件、ABI、工具链及各自产物哈希；同一案例内两种修改不能把收益相加。

## 当前代码契约

`configs/research-hypotheses.yaml` 是有证据的启动假设，不是测评结果。批次通过 `hypotheses` 字段载入，验证本项目账本证据和唯一 `transformation_id` 后，由同一个调度器安排隔离 coder。全局 Codex 会话负责后续规划，coder 会话彼此独立。批次的 `src/` 身份固定，不能在运行时改写；新结构只修改自己的隔离源码，`vendor/official/` 永远不修改。

若结构有真实可调能力，coder 在 `workspace/implementation-input/capabilities.json` 交付 `family_id`、`mechanism_id`、受影响案例/算子、合法变量域、**1–6 个完整参数元组**、必要关卡和停止条件。控制器补上研究记录与冻结源码哈希后校验：只允许作用于目标案例、字段必须在真实配置中存在、种子不同于基准且不重复。程序仅展开声明的元组，不构造未经声明的笛卡尔积；每个种子仍要构建、核对 ASM、做功能和时序检查。没有有效族内变量时，只保留单案和组合证据，**不再把任意 P1 结构送去扫 W2 preload，也不把任意 D1 结构送去扫 W2 load group**。

编码阶段只能从 `workspace/implementation-baseline.json` 复制候选配置并交付代码；不得自行运行 `lab run` 或改动隔离账本。控制器会拒绝账本、冻结报告被改的交付。如果资源账已经否证机制，coder 可交付带机制 ID、原因和可核对证据的 `workspace/implementation-input/stop.json`；控制器验证生成器未变后记为**静态否证**，不伪造功能失败或周期。

常规根生成器参数仍受 `search/targets.py` 的固定域约束。实现族参数必须由本族清单和来源哈希同时授权；AI 自述不能新增合法字段或绕过面积、RF、功耗及正确性约束。研究准入可以保留小幅退化的真实单案，但不得把它称为合格最高分。超功耗结果保留真实周期与功耗，不能进入合格榜；超时/OOM 与性能差分开。

## 供给控制与预算

`search/supply.py` 每次主控 tick 估计可执行任务余量，不依赖新观测到达。它区分已就绪评估、结构编码、阶段等待和预算阻塞；结构任务不会被当作可立即消费的候选。余量不足且活跃结构少于目标数时，只生成一个幂等全局规划请求。相同证据下的空答复有限退避，最多再次请求一次；仍无合法方向时记录原因并允许批次正常结束。**32 个 worker 是容量上限，不用重复或明显低价值实验填满。**

结构编码、结构验证和独立整案分别有并发上限，但都使用同一资源准入。一个族在验证时，另一个族可以编码。官方整案预算主要花在有希望的兼容组合上；不能让每个新结构先搭过时另一案跑一遍。预算在恢复时不重置，也不能隐式提高；用尽后另开经授权的批次。

看板显示已审计最佳、P1/D1 周期、实时任务，以及供给余量、活跃实现族和阻塞原因。`active=0` 可能是等待规划、编码、预算或真实空间耗尽，不等于进程故障。当前最高成绩以账本中 `eligible=true` 且 `audited=true` 的官方整案为准，README 或本文中的历史数字不得冒充实时状态。

## 第一组不同机制的研究

当前启动池只放少量可否证方向，详细任务书在 `configs/research-hypotheses.yaml`：

1. **P1 W2 四路归并拓扑。** 已准入的 N/K 滚动归并 M16 研究版为唯一父版；新提案必须用 `parent_record` 指向其研究记录。先静态证明交换、RF 与事件依赖，再做并行树归并对照。父版 396,045 周期仍慢于全局 P1 最佳 391,510 周期，局部改善不能称作刷新最佳。
2. **P1 QKV 到 attention 的 head 布局边界。** 先用当前最佳 profile 确认边界的绝对成本；只有存在可改变的实测开销才交付默认关闭的有界模板。上一轮 FFN 逐 M 微块方案已被权重重读静态账否证，不重复投入。
3. **D1 head 对齐的热步骤边界。** 冷首步搬运已有小收益；本轮只挑后续各步重复的一个有证据的布局或交换边界。不得越过 `STEP.COMMIT` 提前读未来 token。

结构提案可以填写可选的 `parent_record`。未填写时从相同硬件的已审计单案最佳源码开始；填写时只接受仍可取回、功能通过、功耗合格且研究准入的记录。控制器核对父版源码哈希、硬件与 ASM 哈希及真实报告，在隔离副本恢复父版生成器，并重新构建、逐字节验证三份基线产物。父版记录不存在或身份漂移就拒绝，不能退回全局最佳后继续编码。AI 快照展示可用研究父版，并明确要求显式填写该字段。明显退化的 W1 研究版未获准入，不会自动沿用。

W1 全组/半组输入对齐已使 P1 从 391,510 分别退化到 406,411/396,982 周期；两种实验的 HBM 读取减少而 NoC 与所测 RF 绝对服务周期没有下降。这只否定当前同步机制，不能外推为整个 W1 无机会。新方向应改变数据复用对象、跨算子生命周期或每步重复工作，并同时记录可能增加的成本。

## 运行、验收与清理

先使用 `./lab pipeline configs/pipeline.yaml` 检查任务和预算，再用 `--execute` 启动新批次；恢复必须使用同一配置与 `--resume`。新结构的控制器和候选分别记录来源、配置、硬件和 ASM 身份。隔离结果先做 seed7/123 功能与竞态验证；最后的评分、功耗和资格仍以冻结官方工具为真值。对能力清单、供给幂等、阶段容量、组合来源、预算和恢复运行回归测试，再用少量真实 pilot 验证整个闭环。

历史普通候选只保留配置、关键指标、失败原因和研究结论。最高已审计来源、必要回退和课程材料保护在 `data/releases/`、`data/agent-trace/` 与迭代记录。`workspace/` 是可清理运行区；先用 `./lab clean --dry-run` 列出具体路径与原因，不能清理正在运行批次。网站上传与本地自动搜索分开，沿用至少提升 1,000 分、间隔十分钟的提交规则。
