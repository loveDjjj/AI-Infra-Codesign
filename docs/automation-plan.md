# 自动优化：当前能力与下一步

目标是在固定 wall-clock、CPU、内存和官方整案预算内，最大化「最高已审计合格分数／真实时间」。芯片周期与搜索吞吐分别记录；缓存命中节省主机时间，不代表芯片更快。

## 当前链路

```text
结构化目标 → 静态检查 → 隔离构建 → 产物去重 → 功能检查 → 单案时序
      ↓                                      ↓
全局 Codex 分析 ← 轻量实验账本 ← 同硬件 P1/D1 组合 → 官方整案 → 审计
      ↓
新目标或隔离结构提案
```

程序负责事实、合法性、缓存、预算、调度与发布审计；Codex 负责解释真实结果、提出有界目标和结构假设。全局规划会话指针留在 `workspace/ai-sessions/global.json`，课程轨迹留在 `data/agent-trace/`。生成器在批次运行中冻结；结构编码使用隔离源码。完整官方评分不使用探索缓存，网站上传默认关闭。

当前最高已审计整案是跨源码组合 `pair-w2-throttle-highest-full-1790611520350037544`，49,420.082119 分。它已通过课程 ZIP 独立再生与三份产物哈希核对。根目录已晋升版本仍是 joint28，47,957.061887 分。最近的真实 `closed-loop-result-ai` 批次证明 AI 能提出并注入目标、构建与做功能检查；其后单案时序因主控中断留下孤儿状态，没有证明无人值守跨多轮收敛。后续不能把已实现接口等同于长期实测闭环。

## 轻资产事实政策

`data/experiments.jsonl` 保存每次实际评估的完整配置、周期、功耗、得分、失败原因、主机耗时与来源哈希。资源 profile 只保留压力最高的少数资源及等待假设；详细事件日历只保留在受保护最佳原件。`data/decisions.jsonl` 保存 AI 结论、证据 ID、新目标和精简观测，不复制大型时序 JSON。历史候选清理后标为 `record_only`；最高分、其两案最佳来源、当前基线和课程回退点保留完整源码与原始报告。`workspace/` 可清理，但 AI 会话指针与搜索环境继续保留。实时看板从账本读取，不依赖旧产物；离线 HTML 只按需生成。

`./lab clean --dry-run` 给出具体目录与预计空间；`./lab clean --apply` 在没有搜索进程时先压缩账本，再删除过期产物。清理不会碰 `data/agent-trace/`、`data/iteration-log.md` 和冻结官方工具。运行中批次的完整状态只存在于工作区；执行清理意味着放弃那些批次的 `--resume`，新研究需另开批次。

## 效率和正确性边界

- 多候选使用有界进程池，官方整案保留独立槽位；构建器与模拟器不在线程间共享可变状态。
- 配置去重之后仍核对硬件与 ASM 字节；只有真实输入、工作负载、官方版本和种子身份吻合才复用评估缓存。跨源码同字节程序可以复用探索时序，完整官方验收必须独立执行。
- 功能失败、超功耗、超时、OOM 分开记录。超功耗结果的真实周期和功耗仍是有用观测；基础设施失败不能训练成低分设计。
- TPE 可利用经核实的历史缓存结果，但同一个 study 不重复计权；Random 是比较基线。硬剪枝仅用于已证明非法的约束，经验退化只能降优先级。
- 不同源码的 P1/D1 组合分别再生各自 ASM，并核对同硬件/ABI/官方身份；同一案例的两种优化不能直接加和。
- `vendor/official/`、成绩报告与课程轨迹不改写。`lab package` 与 `lab verify` 是发布前的独立校验。

## 最高优先级：补全真实无人值守验证

1. 为当前生成器建立小型能力清单。目标注入前核对每个变量在该源码版本的合法值与影响案例；最近 AI 提出的 W2 preload 32/64 在冻结生成器上不可构建，不能再浪费建造任务。
2. 在新的批次中跑两轮真实闭环：目标注入、功能、时序、AI 根据结果再提案、同硬件组合、完整官方评分及审计。记录每一步的耗时、有效新产物率和失败原因；中断后检查恢复边界。
3. 把结构验证内部的默认再生、回归、功能、时序变成可独立恢复的阶段任务。结构 A 测评时允许结构 B 编码，但二者受同一资源预算控制。只有能力和证据经校验的新实现族才能进入全局搜索。
4. 用固定候选集测量清理后的冷启动吞吐、缓存复用、无效构建率、供给空窗与最高分随时间变化。只有数据证明收益时再引入更复杂的采样器或 MILP/CP-SAT 求解后端。

## 值得研究的结构方向

- **P1 W2 输入复用与 M/N/K 分片**：比较不同输出分片复用输入的收益，与 RF 常驻权重、partial reduction 和功耗的代价。按指令推导的逻辑读取不等同于实测 HBM 流量。
- **W1–GELU–W2 流式化**：首版 M2 行块每层可能重载约 128 MiB 权重，却只希望省去约 1 MiB 中间激活；时序超过 41 分钟且无结果。新版本先静态证明权重复用，再送昂贵时序。
- **局部同步与错峰**：直接去掉 W2 每行屏障曾使功耗从约 19.16 W 到 21.70 W、周期也退化。下一步按真实依赖区分同步等待和功耗限制，不把 busy 比例当成因果证明。

成功标准是同等预算下更快取得可靠的新事实和更高的已审计分数；CPU 使用率高、AI 调用频繁或目录里产物多，都不是成功本身。
